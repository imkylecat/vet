Vet

Lua-first schema validation with type inference.

local v = require(ReplicatedStorage.Packages.Vet)

local Name = v.string():min(3):max(22)

Name:parse("kyle") --> "kyle"
Name:parse("ky")   --> errors

Types​

Issue​

</>
interface Issue {
path: {string | number}--

Location of the failure inside the value

message: string--

Human-readable description of the failure

}

Failure​

</>
type Failure = {
success: false,
issues: {Issue}
}

The unsuccessful arm of Vet.Result. Naming it lets a helper return a failure that fits any Result<T> without widening T to any.

Result<T>​

</>
type Result<T> = {
success: true,
value: T
} | Failure

Returned by safeParse. Narrow it with if result.success then to get a typed result.value.

infer<S>​

</>
type infer<S> = thevaluetypeproducedbyschemaS

Extracts the type a schema parses to, so a schema can be the single source of truth for both validation and types. 

local Username = v.string():min(3)
type Username = v.infer<typeof(Username)> --> string

local Nickname = v.string():optional()
type Nickname = v.infer<typeof(Nickname)> --> string?

Given a union of schemas, the result is the union of what each one parses to: Vet.infer<StringSchema | NumberSchema> is string | number.

This is a user-defined type function, so it runs during analysis and costs nothing at runtime. It requires a Luau version that supports user-defined type functions.

objectOutput<S>​

</>
type objectOutput<S> = therecordtypeashapeofschemasparsesto

Maps { name: StringSchema, age: NumberSchema } to { name: string, age: number }. Used to type the result of Vet.object, so the shape you pass in is the only place the field types are written down.

The property walk duplicates the one in Vet.infer because a type function cannot call another type function.

AnySchema<T>​

</>
type AnySchema<T> = {
parse: (
self,
unknown
) → T,
safeParse: (
self,
unknown
) → Result<T>
}

The shape every schema shares. Constructors that take another schema accept this, so passing something that is not a schema is a type error at the call site rather than a failure at parse time.

UuidVersion​

</>
type UuidVersion = "v4" | "v5" | "v6" | "v7" | "v8"

Versions accepted by Vet.uuid and Vet.guid. Version 4 is random, 5 is name-based, 6 is reordered time, 7 is Unix epoch time, and 8 is custom.

literal​

Constructor
</>
Vet.literal(
value: T--

The only value the schema accepts

) → LiteralSchema<T>

Creates a schema that accepts exactly value, compared with ==.

local Consented = v.literal(true)

Consented:parse(true)  --> true
Consented:parse(false) --> errors: expected true, got false

Luau widens a literal argument when it infers a generic, so the result is typed boolean rather than true. Annotate the schema if you need the singleton: local Kind: LiteralSchema<"player"> = v.literal("player").

uuid​

Constructor
</>
Vet.uuid(
options: UuidOptions?--

Pass { version = "v4" } to pin the version

) → StringSchema

Creates a schema that accepts a UUID: 8-4-4-4-12 hexadecimal digits, in either case, carrying a version of 1 to 8 and an RFC 9562 variant. 

local Id = v.uuid()
local SessionId = v.uuid({ version = "v7" })

Id:parse("01912d68-783e-7cc0-a2f0-5f8b1d3e9a7c") --> ok
SessionId:parse("6f9619ff-8b86-4d11-b42d-00cf4fc964ff")
--> errors: expected a v7 uuid, got v4

Because the version and variant are checked, the nil UUID and the max UUID are both rejected. Use Vet.guid when you only care about the layout.

The result is a plain StringSchema, so :optional(), :default() and Vet.infer behave exactly as they do for any other string.

Errors

TypeDescription
"unknown uuid version ..."Thrown when `options.version` is not v4 to v8

guid​

Constructor
</>
Vet.guid(
options: UuidOptions?--

Pass { version = "v4" } to pin the version

) → StringSchema

Creates a schema that accepts a GUID: the same 8-4-4-4-12 layout as Vet.uuid, optionally wrapped in braces, with no variant requirement. 

local Id = v.guid()

Id:parse("{6F9619FF-8B86-D011-B42D-00CF4FC964FF}") --> ok
Id:parse("6f9619ff-8b86-d011-b42d-00cf4fc964ff")   --> ok

This is the shape HttpService:GenerateGUID returns, which is braced and uppercase by default. Values Microsoft produced do not always follow the RFC variant rule, so only the layout is enforced unless you pass a version.

Errors

TypeDescription
"unknown guid version ..."Thrown when `options.version` is not v4 to v8

array​

Constructor
</>
Vet.array(
item: S--

Schema every element must satisfy

) → ArraySchema<Vet.infer<S>>

Creates a schema that accepts an array of item.

local Scores = v.array(v.number():integer())

Scores:parse({ 1, 2, 3 }) --> { 1, 2, 3 }
Scores:parse({ 1, 1.5 })  --> errors: [2]: expected an integer, got 1.5

tuple​

Constructor
</>
Vet.tuple(
positions: {S}--

One schema per position, in order

) → TupleSchema<Vet.infer<S>>

Creates a schema that accepts a fixed sequence, checking each position against its own schema. 

local Waypoint = v.tuple({ v.string(), v.number():integer() })

Waypoint:parse({ "spawn", 3 }) --> { "spawn", 3 }
Waypoint:parse({ "spawn" })    --> errors: [2]: expected number, got nil

Luau infers a mixed array literal as a union of its element types, so the positions are already merged by the time a type function can see them. The result is therefore { string | number } rather than a true positional type — the runtime check is exact, the static type is not.

object​

Constructor
</>
Vet.object(
shape: S--

Table mapping field names to schemas

) → ObjectSchema<Vet.objectOutput<S>,S>

Creates a schema that validates a table field by field. The field types come from the shape, so the schema is the only place they are declared. 

local User = v.object({
	name = v.string():min(3),
	nickname = v.string():optional(),
})

type User = v.infer<typeof(User)> --> { name: string, nickname: string? }
